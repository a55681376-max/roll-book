# 전자출석부

브라우저에서 사용하는 전자출석부입니다. 프로그램, 참여자, 전자서명, 출석 기록과 A4 인쇄를 지원합니다.

## 화면 사용 방법

1. 첫 화면에서 **담당자 인증** 또는 **관리자 인증**을 선택합니다.
2. 아이디와 비밀번호를 입력합니다.
3. 담당자 인증 후에는 **참여자 출석** 화면이 열립니다. 참여자가 이름을 선택하고 서명합니다.
4. 상단 **담당자** 버튼을 누르고 다시 로그인하면 **프로그램 관리 / 참여자 관리 / 출석 관리 / 인쇄**를 사용할 수 있습니다.
5. **참여자 출석** 화면으로 돌아가면 담당자 관리 인증이 종료됩니다. 관리 화면에 다시 들어갈 때는 로그인해야 합니다.
6. **로그아웃**을 누르면 첫 화면으로 돌아갑니다. 새로고침한 경우에도 첫 화면에서 인증합니다.

왼쪽에는 프로그램 관리·참여자 관리·출석 관리·인쇄 탭을, 오른쪽에는 **담당자 계정 관리** 탭을 둡니다. 계정 관리에서 로그인한 아이디를 확인하고 현재 비밀번호 확인 후 비밀번호를 변경합니다.

## 공휴일 자동 휴강

프로그램 정보를 저장한 후 **요일 기준 회차 자동 재생성**을 누르면 구글의 공개 대한민국 공휴일 달력을 확인합니다. 별도 가입이나 인증키는 필요하지 않습니다. 공휴일·대체공휴일·달력에 반영된 임시공휴일 및 선거일은 휴강으로 지정하고 이름을 표시합니다. 일반 토요일·일요일은 지정한 프로그램 요일대로 진행합니다.

휴강은 총 수업 회차에 포함하지 않고 다음 날짜까지 생성합니다. 마지막 수업이 운영기간을 넘으면 종료일을 늘리며 저장 전 회차 수와 마지막 수업 날짜를 확인합니다. 기존 수동 휴강, 같은 날짜의 회차 ID와 메모를 유지합니다. 출석 기록이 있는 회차를 제거하거나 휴강·회차 번호를 바꾸는 재생성은 중단합니다.

자료 제공자가 새 임시공휴일을 반영한 뒤 재생성하면 적용됩니다. 이미 저장한 일정은 자동으로 덮어쓰지 않습니다. 공개 달력의 제공 범위와 업데이트 시점에 영향을 받으며 조회 실패나 자료 없는 연도는 기존 일정을 유지합니다. 서버는 자료를 최대 1시간 캐시합니다.

## 관리자 설정

관리자 인증 후에는 **설정** 화면을 사용합니다.

연결 설정·백업·복원은 관리자 화면의 **데이터 관리**에서 사용합니다. 데이터 초기화 기능은 제공하지 않습니다.
참여자 출석 화면에는 회차와 날짜(예: 1회차 (2026년 10월 16일)), 이름 선택 및 서명 안내를 표시합니다. 아이콘은 단색 라인 스타일로 통일합니다.

- **담당자 계정 목록**: 번호, 아이디, 등록일시, 메모 순서입니다. 계정 수정과 사용 중지를 지원합니다. 사용 중지는 원본 계정을 삭제하지 않습니다.
- **+ 새 담당자 등록**: 번호와 등록일시는 자동 기록됩니다. 아이디, 비밀번호, 메모를 입력합니다. 메모는 관리자만 확인합니다. 수정 화면에서 비밀번호는 바꿀 때만 입력합니다.
- **관리자 계정 변경**: 아이디, 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 입력합니다. 현재 비밀번호가 맞아야 저장됩니다.

기존 계정과 출석 데이터는 그대로 사용합니다. 기존 최고 관리자 계정은 관리자, 기존 일반 관리자 계정은 담당자 역할로 사용합니다.
기존 아이디와 비밀번호를 유지합니다. 비밀번호 원문은 서버 응답이나 공개 코드에 포함하지 않습니다.

## 의견함

담당자 관리 화면의 **의견함**에서 **의견 쓰기**로 제목과 내용을 보내고, **내 의견**에서 본인이 보낸 의견과 답변을 확인합니다. 관리자 인증 후에는 설정 화면의 **의견함**에서 **전체 의견**을 보고 상태와 답변을 저장합니다. 상태는 **접수 / 완료 / 보류 / 불가**입니다. 새 답변 표시는 담당자가 해당 의견을 열어 확인하면 사라집니다. 첨부파일과 외부 알림은 사용하지 않습니다.

의견은 출석 자료와 분리된 서버 전용 테이블에 보관합니다. 서버는 세션의 만료·계정 버전·사용 중지·역할·담당자 관리 인증을 검사하며, 담당자는 본인 의견만 조회할 수 있습니다. 답변 수정은 버전 확인으로 덮어쓰기를 막습니다. 목록은 최근 200개를 표시합니다. 신규 서버에 설치할 때는 기존 인증 설정 후 `supabase_feedback.sql`을 적용하고 `supabase/functions/rollbook-api/index.ts`를 배포합니다. 기존 계정과 출석 자료는 변경하지 않습니다.

`tests/feedback-security.sql`은 임시 테스트 계정·의견으로 권한과 읽음 처리를 검사하고 모든 변경을 롤백합니다.

## 인쇄 화면

인쇄 화면에서 가로형 또는 세로형을 선택합니다. 선택한 프로그램 이름을 제목으로 사용하며 제목 아래 회차 범위는 표시하지 않습니다. 운영요일과 시간은 별도 칸에 함께 표시합니다. 회차 칸 너비를 같게 맞추며 마지막 페이지도 같은 칸 배치를 유지합니다. 관리 메뉴와 안내 카드는 출력하지 않습니다. 참여자 등록 양식의 파일 이름은 **전자출석부 참여자 등록 서식.xlsx**입니다.

## 실행 및 배포

### 내려받은 파일을 컴퓨터에서 실행하기

`index.html`을 더블클릭하면 `file://` 주소로 열리며 바로 로그인해서 사용할 수 있습니다. 별도 로컬 서버나 바로가기는 필수가 아닙니다. 로그인, 자료 연결, 공휴일 확인에는 인터넷 연결이 필요합니다. 계정과 출석 자료는 기존 서버를 그대로 사용합니다.

사용자 요청에 따라 서버는 파일 직접 실행의 `Origin: null`을 허용합니다. 이는 특정 파일이나 컴퓨터만 허용하는 설정이 아닙니다. 비밀번호 검사, 로그인 시도 제한, 세션 만료, 역할별 권한과 DB 직접 접근 차단은 그대로 적용합니다. 파일에서 공휴일을 조회할 때는 기존 `rollbook-api`의 `holidays` 요청으로 세션 인증 후 공휴일 자료만 받습니다.

Windows에서는 `start-local.cmd` 또는 바탕화면의 **전자출석부** 바로가기를 더블클릭합니다. 로컬 서버가 켜지고 기본 브라우저에서 **http://127.0.0.1:8765** 가 자동으로 열립니다. 이미 같은 프로젝트 서버가 실행 중이면 새 서버를 만들지 않고 브라우저만 엽니다. 다른 프로그램이나 샘플 서버가 포트를 사용하면 종료하지 않고 안내합니다. Node.js가 필요하며 Codex에 포함된 Node.js가 있으면 자동으로 사용합니다. 터미널에서는 프로젝트 폴더에서 `node tools/local.cjs`로 실행할 수 있습니다. 브라우저를 열지 않고 서버만 확인할 때는 `node tools/local.cjs --no-open`을 사용합니다.

이 실행 방식은 **실제 계정과 실제 출석 데이터**에 연결됩니다. 저장한 변경은 다른 기기에도 반영됩니다. 샘플 화면만 확인하려면 기존 `node tools/preview.cjs`를 사용합니다. 두 도구는 같은 포트를 사용하므로 동시에 실행하지 않습니다. 실행 창에서 Ctrl+C를 누르면 종료합니다.

Netlify 배포 한도와 관계없이 로컬에서 수정 결과를 확인할 수 있습니다. 로컬 파일 수정은 GitHub 업로드나 Netlify 배포를 자동으로 수행하지 않습니다.

웹 화면과 공휴일 조회용 Netlify 함수를 배포합니다. 실제 로그인과 자료 저장에는 설정된 Supabase 서버가 필요합니다.
GitHub main에 변경사항을 올리면 연결된 Netlify 사이트 https://roll-book.netlify.app 에 자동 배포됩니다. 로그인 서버의 허용 주소도 이 주소와 일치해야 합니다.

## 데이터 저장

기존 public.attendance_data 테이블과 행을 보존합니다. supabase_security.sql은 원본 보관, 서버 계정·세션 관리, 인증 API, RLS 설정을 기록한 보안 전환 스크립트입니다. 인증되지 않은 브라우저의 직접 테이블 접근은 RLS와 권한에서 모두 차단합니다.

인증은 Supabase Auth가 아닌 서버의 rollbook-api 함수와 rollbook_api에서 처리합니다. 브라우저에서 DB 함수를 직접 호출할 수 없으며 서버만 실행합니다. 비밀번호는 bcrypt 해시로 보관하고, 무작위 세션 토큰의 해시를 서버에 저장합니다. 토큰은 브라우저 메모리에만 유지하며 8시간 후 만료됩니다. 관리자만 계정에 접근하고, 출석 화면에서는 기존 참여자·회차의 출석 기록만 수정합니다. 담당자 관리 화면으로 들어갈 때는 다시 인증합니다.

공개 코드에는 publishable 연결키만 사용하며 비밀키와 service_role 키를 넣지 않습니다. 비밀키 입력도 거부합니다. 참여자 자료와 비밀번호는 localStorage에 새로 저장하지 않습니다. 인증 후 예전 브라우저 캐시는 제거합니다.

변경 전 자료를 서버 전용 state_history에 자동 보관합니다. 다른 기기가 먼저 수정한 경우 덮어쓰지 않고 새로고침을 안내합니다. 인증된 자료는 10초 간격으로 갱신하며 수정 창이 열려 있거나 저장 중일 때 갱신하지 않습니다.

새 프로젝트에 보안 스크립트를 그대로 실행하기 전에 기존 계정 원본과 자료가 준비되어 있는지 확인해야 합니다. 공개 접근을 허용하는 과거 정책은 재사용하지 않습니다.

## 사용 기술

HTML5, CSS3, Vanilla JavaScript, Canvas 전자서명, SheetJS 엑셀 처리, Supabase JS v2, PostgreSQL 및 pgcrypto.

## 개발 확인

- node tests/auth-check.cjs: 서버 API 연동 흐름, 역할 구분, 계정 변경, 비밀번호 가림, 세로·가로 인쇄 검사
- node tests/holidays-api.mjs: 공휴일 달력 파싱, 자료 미제공 연도와 연결 실패 처리 검사
- node tests/cloud-security.cjs: 배포된 서버 API와 인증 없는 테이블·DB 함수 접근 차단 검사 (자료를 변경하지 않음)
- node tools/preview.cjs: http://127.0.0.1:8765 에서 실제 DB 요청을 하지 않는 샘플 화면 실행. 샘플 인증 정보는 tools/preview-api.js에만 있으며 실제 사이트에서는 사용할 수 없습니다.

기획 요구사항은 노인복지관_전자출석부_PRD_v0.1.md, 디자인 참고는 DESIGN.md와 DESIGN2.md에 있습니다.
